手势控制 · 花朵绽放

项目交付讲解 —— 从摄像头到花朵，一共三层楼

MediaPipe 手势识别 Canvas 逐帧渲染 Web Worker 后台编码 IndexedDB 本地缓存

用键盘 ← → 或下方按钮翻页。共 10 页。

一句话原理：摄像头看到手掌张合 → 变成一个 0~100% 的数值 → 用这个数值控制花朵画面"显示哪一帧"。
握拳 = 花苞，手掌张开 = 完全绽放。

数据流总览：一条流水线

整个项目就是这条流水线在每一帧地循环。讲给别人听，讲这一条线就够了。

摄像头画面→ 找出手的 21 个关键点→ 算出张开度 0~1→ 映射成帧号→ 画布绘制
张开度：手掌"张合程度"的数值。握拳 ≈ 0.9~1.1，完全张开 ≈ 1.5~1.8（原始值），映射后变成 0~1。
它就是整个项目的"旋钮"，其他一切都是在服务这个旋钮。

重点：这个数值是连续的，所以花是"渐变绽放"，不是开关。

三层架构

全部跑在一个网页里，没装任何软件、没用任何前端框架（没有 Vue / React）。

3
呈现层 — Canvas 逐帧绘制
花朵 = 362 张图片组成的序列，手势决定显示第几张
2
识别层 — MediaPipe HandLandmarker
Google 开源模型，浏览器本地运行，每帧输出手的 21 个关键点坐标
1
基础层 — 浏览器原生 API + 本地服务器
getUserMedia 摄像头 / IndexedDB 缓存 / Web Worker 后台线程 / Python 起本地服务
为什么必须有本地服务器？浏览器安全规定：只有 localhost / https 开头的网页才允许调用摄像头。直接双击 HTML 文件打开是不给权限的。

手势识别：张开度怎么算出来的

点击按钮切换姿势，看关键点和距离线的变化。

张开度 =（4 个指尖到手腕的平均距离）÷ 手掌长度
4 个指尖 = 食指/中指/无名指/小指的指尖；手掌长度 = 手腕到中指根。
  • 握拳时：指尖离手腕近 → 数值小（约 1.0）
  • 张开时：指尖离手腕远 → 数值大（约 1.6）
  • 用比值而不是像素距离：手离镜头远近会变，相除后自动抵消 —— 这是整个算法里最关键的一步

为什么不直接拖动视频播放器？

mp4 是压缩格式：只有"关键帧"（标 I 的格子）能独立解码，中间的帧必须靠前面的帧推算。点下面任意一帧对比两条路的差别：

所以手势快速拖动原生视频必然一顿一顿；想丝滑，就得把视频拆开。

让它"又快又稳"的三件套

A
Web Worker 后台编码
把 362 张图转 JPEG 的重活放到后台线程，主线程只管绘制 —— 页面不卡。
B
IndexedDB 本地缓存
提取结果（约10MB）存进浏览器数据库，第二次打开秒加载，不用重新提取。
C
缓存内容体检 + 自愈
每次加载抽 5 帧对比画面差异，"全长一个样"的坏缓存自动扔掉重新提取 —— 专治不同浏览器解码时序不一致。
另外两处细节：数值平滑（EMA 指数滑动平均，防手抖导致画面抖动）；只在摄像头出新帧时才跑识别（省一半性能）。

踩坑实录（每一坑 = 一个知识点）

坑1 · 在 ZCode 内置浏览器里完全不动

内置浏览器拿不到摄像头权限（NotAllowedError）。摄像头 API 有安全限制：必须是 localhost / https 且是受信任的浏览器。→ 教训：先确认环境，再查代码。

坑2 · 手势正常但花不响应

"视频加载完成"事件的监听器挂晚了，事件早就发完了，永远等不到。→ 教训：依赖事件不如直接查状态（readyState）。

坑3 · 提取出362张一模一样的图

seek 跳帧时事件触发了，但新画面还没解码完，抓到的全是旧帧。→ 教训：改成"播放式抓帧"——每帧真正呈现时才抓（rVFC），机制上杜绝。

坑4 · 提取时页面卡成幻灯片

JPEG 编码把主线程堵死，视频播放都被拖慢。→ 教训：重活放 Web Worker。

坑5 · 进度卡在99%

暂停状态下部分回调永不触发。→ 教训：所有异步等待必须有超时兜底，永远不能裸等一个事件。

坑6 · 花只动一点点像没动

手进出画面的误检数据把校准范围撑爆（0.37~3.89），正常动作只映射到 18%~35%。→ 教训：统计分位数 + 离群值拒绝，校准自愈。

坑7 · 换台电脑又不响应

那台电脑缓存里存了坏帧。→ 教训：缓存加载时做内容体检，坏缓存自动重提取（自愈）。

给人讲的时候可以总结成一句：技术原理不难，难的是浏览器环境的时序与不可控 —— 所以最后做了自检报告 + 自愈机制。

你需要具备的知识清单

必懂（讲清项目足够）

  • JavaScript 异步：Promise / async-await
  • Canvas 2D：画图、requestAnimationFrame 循环
  • 几何小算法：两点距离 + 归一化比值
  • 浏览器安全模型：localhost / https 才能开摄像头
  • 视频压缩常识：关键帧（I帧）是什么

进阶（被追问时能答上）

  • MediaPipe：浏览器里跑的轻量神经网络（WASM/GPU）
  • Web Worker / OffscreenCanvas：主线程与后台分工
  • IndexedDB：浏览器里的本地数据库
  • EMA 指数滑动平均：平滑系数的权衡
  • rVFC：逐帧呈现回调（抓帧的正确姿势）

一句话总结（收尾用）

"整个项目 = 一个网页 + 一个手势识别模型 + 一叠图片。摄像头喂画面给识别模型，模型吐出一个 0 到 1 的张开度，我用它当进度条旋钮，去翻那一叠图片。所有难度都在'让它在任何浏览器里都稳定'这件事上。"

现场演示建议

  • 先演示红芍药版（原始素材）→ 再切蓝玫瑰版（AI 生成素材）→ 最后代码花版（纯手绘）
  • 演示顺序体现对比：真实素材 / AI 素材 / 纯代码渲染三种路线
  • 被问"和抖音那个什么区别"：原理相同（手势控制视频进度），区别在我们把视频拆成了帧序列 + 加了自愈机制，不依赖特定环境
